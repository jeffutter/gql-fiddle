## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found while reviewing TASK-123 (live-sync/). TASK-123 deleted live-sync/pnpm-lock.yaml and live-sync/pnpm-workspace.yaml and .gitignore'd them, but only treated the symptom (git-tracked debris), not the root cause: nothing stops pnpm from being invoked against live-sync/ (an npm project — tracked package-lock.json, no packageManager field). Verified live during this review: pnpm had been run against live-sync/ again since TASK-123 closed, regenerating both gitignored files and reinstalling node_modules via pnpm's content-addressed store. This broke 'nix develop -c npm --prefix live-sync test' with 'Module did not self-register: .../better-sqlite3/build/Release/better_sqlite3.node' (14/26 tests failing) until better-sqlite3 was manually rebuilt with npm. The .gitignore entries hide the recurrence from git status but do nothing to prevent it, so this class of breakage will keep recurring silently. Axis: Resilient.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
SETUP (read first): This is a Rust+WebAssembly core (crates/gql-core) with a TypeScript/React web app (web/). ALL commands must run inside the Nix dev shell: either run 'direnv allow' once, or prefix every command with 'nix develop -c'. Work from the repository root unless told otherwise. Do not change pinned dependency versions. This ticket is scoped to live-sync/ (a standalone Cloudflare Worker that uses npm, not pnpm — its tracked lockfile is live-sync/package-lock.json).

1. Check the npm version available in the Nix devshell: run 'nix develop -c npm --version'. Add a top-level field to live-sync/package.json: "packageManager": "npm@<that-version>" (directly under the "version" field, before "scripts").
2. In live-sync/package.json's "scripts" object, add a "preinstall" script: "preinstall": "node -e \"if (!/npm/.test(process.env.npm_config_user_agent||'')) { console.error('live-sync is an npm-only project — do not run pnpm/yarn install here. Use: npm --prefix live-sync install'); process.exit(1); }\"". Keep it as a single-line inline check; no new dependency or separate script file.
3. Verify the guard works: run 'nix develop -c bash -c "cd live-sync && npm_config_user_agent=pnpm/9.0.0 npm run preinstall"' and confirm it exits non-zero with the error message; then run 'nix develop -c npm --prefix live-sync run preinstall' (normal npm user agent) and confirm it exits 0.
4. Do a clean reinstall to prove npm still works end-to-end: 'rm -rf live-sync/node_modules && nix develop -c npm --prefix live-sync install'.
5. Run: nix develop -c npm --prefix live-sync test — confirm 26/26 tests pass.
6. Run: nix develop -c npx --prefix live-sync tsc --noEmit -p live-sync/tsconfig.json — confirm no type errors.
7. Run: git status to confirm no pnpm-lock.yaml/pnpm-workspace.yaml reappeared and only live-sync/package.json (plus package-lock.json if npm rewrote it) shows as changed.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Added packageManager field (npm@10.9.8) and preinstall guard script to live-sync/package.json. The preinstall script checks npm_config_user_agent for a word-boundary match on 'npm' (not substring, so 'pnpm' is correctly rejected). This prevents pnpm/yarn from silently corrupting node_modules in the live-sync/ directory.
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->

All 4 acceptance criteria verified: packageManager field present, preinstall guard rejects non-npm agents, 26/26 tests pass, tsc clean (pre-existing session.ts WIP errors are unrelated).
